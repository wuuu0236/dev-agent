# 面试速记（Dev-Agent / DataLens）

> 面试前 10 分钟翻一遍。每个话题 = 一句话答案 + 底层逻辑 + 话术。

---

## 1. 项目一句话介绍

> "基于 LangGraph + FastAPI + Streamlit 的 AI Agent + RAG 系统：Agent 能操作文件、搜索知识库；RAG 用业界标准 ragas 做量化评估（0-100 百分制），支持多配置对比；已上线可演示。"

**架构**：Streamlit（人用）/ FastAPI（程序用）/ MCP（AI 用）三种入口，同一套能力。

---

## 2. RAGAS 评估（重点，必问）

**一句话**：RAGAS 是开源 RAG 评测标准，四维指标量化"检索 + 生成"质量，业界认可。

**四指标机制**：
| 指标 | 机制 |
|---|---|
| Context Precision | LLM 逐块判相关性，按排名加权 |
| Context Recall | LLM 判黄金答案关键信息有没有被检索到 |
| Faithfulness | **把答案拆成原子命题，逐条核对上下文** |
| Answer Relevancy | 从答案生成问题，embedding 算相似度（不走 LLM）|

**为什么比我手写的强**："Faithfulness 拆命题验证 + Relevancy 走向量，比一次性打分稳定。"

**局限（主动说=加分）**：也是 LLM-as-Judge 有噪声；平均分掩盖单题分布；强依赖测试集质量；绑 langchain 生态（锁 `<1.0`）。

**踩过的坑（真实经验）**：① DeepSeek 只支持 `n=1` → `bypass_n=True`；② 硅基流动不接受 token 数组 → `check_embedding_ctx_length=False`；③ 数字取决于测试集↔知识库匹配度，库里没有的题 Recall 诚实归零。

---

## 3. Function Calling

**一句话**：让模型用结构化格式"声明"想调哪个工具、传什么参数，由你的代码执行。

**核心**：**模型只声明意图，执行权在你手里** → 所以执行层要做安全检查（三层 path 审查）。

**四步**：定义工具 JSON Schema → LLM 输出 tool_calls → 你执行 → 结果塞回循环。

---

## 4. v1→v2 异常保护

**一句话**：工具调用包 try-except，工具挂了**把错误转译成一条 AI 能读的消息**，而不是崩溃。

**精髓**："异常被转译成对话的一部分，而不是程序的中断。" 错误信息=程序产出，但喂给 AI，AI 再给用户。

---

## 5. LangChain vs LangGraph

**一句话**：LangGraph 是编排框架（控制流），LangChain 是它的底座（消息模型 + 生态），**LangGraph 建在 langchain 之上、离不开它**。

**项目里**：LangGraph 管循环（StateGraph），langchain-core 管消息类型，langchain-openai 接 RAGAS。

---

## 6. 大模型幻觉

**一句话**：幻觉是 LLM 统计本质决定的，目标是**降低 + 可识别**，不是消除。

**三道防线**：
- **防**：RAG 接地（只让说文档里的）+ 允许说"不知道"
- **控**：低温度 + 检索质量（**检索对了就没编的动力**）
- **验**：引用溯源 + RAGAS Faithfulness 拆命题核对（量化幻觉率）

---

## 7. 流式输出

**一句话**：LLM 自回归逐 token 生成，API 用 SSE 边生成边发，前端边收边渲染——**不加速生成，只提前送达部分结果**。

**难题首 token 会变慢吗？会**，但慢在答案开始之前：
- Agent 多调几次工具（每轮一次 LLM 调用）
- 上下文变长 → prefill 更久
- 流式救不了"开始前"，靠状态提示 + 缓存掩盖

---

## 8. 多端用户（产品层 + 工程层，答两层）

**产品层**：多端访问 = 产品从"个人工具"变"多租户 SaaS"，围绕三件事：① 用户与权限（账号/团队/谁能看谁的库）② 协作与信任（共建、引用溯源、私有化部署）③ 商业化（免费引流/按团队收费/企业版）。

**工程层**：① 数据库扛并发（SQLite→PostgreSQL）② 安全（认证+隔离，防 key 泄露）③ 成本（缓存+限流）④ 可运维（指标+告警）。

**金句**："产品定义要什么，工程决定做不做得到。"

---

## 9. 登录与隔离

**一句话**：登录解决"数据归属"，数据库决定"并发能力"，**两者正交**。

**为什么不能用 IP 隔离**：IP 是"你在哪上网"，登录是"你是谁"。IP 会变、可共享（NAT）、可伪造——隔离隔离的是"人"。

**SQLite 场景**：微信手机端用 SQLite 是**本地单机单写者**（对）；服务器多用户并发才换 PostgreSQL（几十人 SQLite+登录够，几百人必须换）。

---

## 10. 可观测

**一句话**：trace 是显微镜，指标是仪表盘。

**三支柱**：日志（发生了什么）/ 指标（多少、多快）/ 追踪（卡在哪一环）。
**项目已有**：Langfuse 追踪（RAG + Agent）。**待补**：结构化日志、Sentry、Prometheus+Grafana、告警。

---

## 11. 项目可优化清单（"还有哪些可优化"）

**产品层**：权限体系、协作、信任/私有化、商业化、首次体验。
**工程层**：测试+CI（最高优先，能拦依赖回归）、安全加固（work_dir 沙箱）、语义缓存、Agent 换 langchain 原生集成、索引查询分离。

---

## 12. 测试 + CI + 语义缓存（概念）

- **测试** = 写代码让机器自动检查功能没被改坏（手动=抽查会漏，自动=全查不忘）
- **CI** = 每次 push 让 GitHub 自动跑测试，绿了才放心（今天的 mcp/langchain bug 都是"import 一下立刻崩"，冒烟测试全能拦住）
- **语义缓存** = 用 embedding 按"意思"命中重复问题，用一次便宜的计算省掉一次昂贵的 LLM 生成

---

## 13. 主动说出来的减分点 → 变成加分点

> "项目现在是单用户定位，能多人打开但不是合格的多用户产品——数据没隔离、并发会锁、成本共用一个 key。所以我认为它是作品集定位，落地多租户需要先做认证隔离、换并发数据库、加缓存限流。"（承认短板 + 说出差距 = 懂生产化）
